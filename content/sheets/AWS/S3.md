# Amazon S3 — Data Engineering Cheat Sheet

_Object storage that serves as the backbone of almost every AWS data lake — raw, staging, and curated zones typically all live here._

---

## Overview

Amazon S3 is the default storage layer for AWS data platforms. It's durable (11 nines), cheap at scale, and every analytics/compute service (Glue, Athena, Redshift Spectrum, EMR, SageMaker) reads from it directly — which is why "S3 as the data lake" has become the default AWS architecture rather than one option among many.

## When to Use S3 (and When Not To)

**Use S3 when:**

- You need a durable landing zone for raw data before it's structured
- Multiple compute engines (Athena, Spark, Redshift Spectrum) need to read the same dataset
- You want to decouple storage costs from compute costs (pay for GB stored, not for a running cluster)
- Data is written once/rarely and read many times (the classic data lake pattern)

**Consider alternatives when:**

- You need sub-millisecond read latency → use DynamoDB or ElastiCache instead
- You need transactional, row-level updates at high frequency → use RDS/Aurora, or Iceberg/Hudi/Delta tables on top of S3 for upsert semantics
- You need a POSIX filesystem for legacy applications → use EFS or FSx instead

## Key Concepts

- **Storage classes:** Standard, Intelligent-Tiering, Standard-IA, One Zone-IA, Glacier Instant/Flexible/Deep Archive
- **Data lake zoning pattern:** `raw/` → `processed/` → `curated/` (or bronze/silver/gold)
- **Partitioning:** Use `key=value` prefixes (e.g. `year=2026/month=09/day=03/`) so Athena/Glue/Spark can prune partitions
- **Event notifications:** Trigger Lambda, SQS, or SNS on `s3:ObjectCreated:*`
- **Versioning + Lifecycle rules:** Protect against accidental deletes; auto-transition/expire old objects
- **Encryption:** SSE-S3, SSE-KMS, or SSE-C; enforce via bucket policy
- **Table formats:** Apache Iceberg, Hudi, and Delta Lake add ACID transactions, schema evolution, and time travel on top of plain S3 objects — increasingly the default for curated zones
- **S3 Object Lambda:** Transform data on GET requests without duplicating it (e.g. redact PII on the fly)
- **Multipart upload:** Required for objects >5 GB; recommended above ~100 MB for resumability

## Common Architecture Patterns

**Medallion / zoned data lake:**

```
raw/          <- immutable landing zone, exact copy of source
  └── source_system/table/ingestion_date=YYYY-MM-DD/
staging/      <- validated, deduplicated, type-cast
  └── table/year=/month=/day=/
curated/      <- business-ready, joined, aggregated (often Iceberg/Parquet)
  └── table/
```

**Event-driven ingestion:**
`Producer → S3 (raw/) → S3 Event Notification → Lambda/SQS → Glue Job → S3 (curated/) → Athena/Redshift Spectrum`

**Cross-account data sharing:**
Use bucket policies + IAM roles (not IAM users) so a consuming account assumes a role scoped to a specific prefix — avoids copying data between accounts.

## Worked Examples

### Example 1: Zoned data lake bucket with lifecycle rules

**Scenario:** You're standing up a new raw landing zone that should auto-archive after 90 days.

```hcl
resource "aws_s3_bucket" "raw_zone" {
  bucket = "acme-data-lake-raw"
}
resource "aws_s3_bucket_lifecycle_configuration" "raw_zone" {
  bucket = aws_s3_bucket.raw_zone.id
  rule {
    id     = "archive-old-raw-data"
    status = "Enabled"
    transition { days = 90; storage_class = "GLACIER" }
  }
}
```

```python
# Verify the zone is ready before a pipeline starts writing to it
def zone_ready(bucket: str) -> bool:
    try:
        s3.head_bucket(Bucket=bucket)
        return True
    except ClientError:
        return False
```

### Example 2: Event-driven ingestion trigger

**Scenario:** Every file landing in `raw/orders/` should kick off a Lambda validator within seconds.

```hcl
resource "aws_s3_bucket_notification" "orders_trigger" {
  bucket = aws_s3_bucket.raw_zone.id
  lambda_function {
    lambda_function_arn = aws_lambda_function.validate_orders.arn
    events               = ["s3:ObjectCreated:*"]
    filter_prefix        = "raw/orders/"
  }
}
```

```python
# Simulate the event locally to test the Lambda before deploying
test_event = {
    "Records": [{"s3": {"bucket": {"name": "acme-data-lake-raw"},
                          "object": {"key": "raw/orders/2026-09-03.json"}}}]
}
response = lambda_client.invoke(FunctionName="validate-orders", Payload=json.dumps(test_event).encode())
```

### Example 3: Cross-account read access for an analytics team

**Scenario:** A separate analytics AWS account needs read-only access to `curated/` without copying data.

```hcl
resource "aws_s3_bucket_policy" "analytics_cross_account" {
  bucket = aws_s3_bucket.raw_zone.id
  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [{
      Effect    = "Allow"
      Principal = { AWS = "arn:aws:iam::999999999999:role/analytics-reader" }
      Action    = ["s3:GetObject", "s3:ListBucket"]
      Resource  = ["${aws_s3_bucket.raw_zone.arn}/curated/*", aws_s3_bucket.raw_zone.arn]
    }]
  })
}
```

```python
# From the analytics account: assume the role, then read
sts = boto3.client("sts")
creds = sts.assume_role(RoleArn="arn:aws:iam::111111111111:role/analytics-reader", RoleSessionName="read-curated")["Credentials"]
cross_account_s3 = boto3.client("s3", aws_access_key_id=creds["AccessKeyId"],
                                 aws_secret_access_key=creds["SecretAccessKey"], aws_session_token=creds["SessionToken"])
cross_account_s3.list_objects_v2(Bucket="acme-data-lake-raw", Prefix="curated/")
```

## Terraform

```hcl
resource "aws_s3_bucket" "data_lake" {
  bucket = "my-company-data-lake-raw"
}

resource "aws_s3_bucket_versioning" "data_lake" {
  bucket = aws_s3_bucket.data_lake.id
  versioning_configuration {
    status = "Enabled"
  }
}

resource "aws_s3_bucket_server_side_encryption_configuration" "data_lake" {
  bucket = aws_s3_bucket.data_lake.id
  rule {
    apply_server_side_encryption_by_default {
      sse_algorithm     = "aws:kms"
      kms_master_key_id = aws_kms_key.data_lake.arn
    }
    bucket_key_enabled = true
  }
}

resource "aws_s3_bucket_public_access_block" "data_lake" {
  bucket                  = aws_s3_bucket.data_lake.id
  block_public_acls       = true
  block_public_policy     = true
  ignore_public_acls      = true
  restrict_public_buckets = true
}

resource "aws_s3_bucket_lifecycle_configuration" "data_lake" {
  bucket = aws_s3_bucket.data_lake.id

  rule {
    id     = "transition-to-ia"
    status = "Enabled"
    filter { prefix = "raw/" }

    transition {
      days          = 30
      storage_class = "STANDARD_IA"
    }
    transition {
      days          = 90
      storage_class = "GLACIER"
    }
  }

  rule {
    id     = "expire-temp-files"
    status = "Enabled"
    filter { prefix = "tmp/" }

    expiration {
      days = 7
    }
  }

  rule {
    id     = "abort-incomplete-multipart"
    status = "Enabled"
    filter {}

    abort_incomplete_multipart_upload {
      days_after_initiation = 3
    }
  }
}

# Bucket policy: enforce TLS + deny unencrypted uploads
resource "aws_s3_bucket_policy" "data_lake" {
  bucket = aws_s3_bucket.data_lake.id

  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [
      {
        Sid       = "DenyInsecureTransport"
        Effect    = "Deny"
        Principal = "*"
        Action    = "s3:*"
        Resource = [
          aws_s3_bucket.data_lake.arn,
          "${aws_s3_bucket.data_lake.arn}/*",
        ]
        Condition = {
          Bool = { "aws:SecureTransport" = "false" }
        }
      },
      {
        Sid       = "DenyUnEncryptedObjectUploads"
        Effect    = "Deny"
        Principal = "*"
        Action    = "s3:PutObject"
        Resource  = "${aws_s3_bucket.data_lake.arn}/*"
        Condition = {
          StringNotEquals = { "s3:x-amz-server-side-encryption" = "aws:kms" }
        }
      }
    ]
  })
}

# Cross-account read access, scoped to one prefix
resource "aws_s3_bucket_policy" "cross_account_read" {
  bucket = aws_s3_bucket.data_lake.id

  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [{
      Sid       = "AllowAnalyticsAccountRead"
      Effect    = "Allow"
      Principal = { AWS = "arn:aws:iam::999999999999:role/analytics-reader" }
      Action    = ["s3:GetObject", "s3:ListBucket"]
      Resource = [
        aws_s3_bucket.data_lake.arn,
        "${aws_s3_bucket.data_lake.arn}/curated/*",
      ]
    }]
  })
}

output "data_lake_bucket_arn" {
  value = aws_s3_bucket.data_lake.arn
}
```

### AWS CLI Quick Reference

```bash
# Sync a local folder to S3 (only uploads changed files)
aws s3 sync ./local_data s3://my-company-data-lake-raw/events/ --delete

# List objects under a prefix with human-readable sizes
aws s3 ls s3://my-company-data-lake-raw/events/ --recursive --human-readable --summarize

# Copy with server-side encryption
aws s3 cp file.parquet s3://my-company-data-lake-raw/events/ --sse aws:kms

# Check bucket size and object count (via CloudWatch metric, not s3 ls, for big buckets)
aws cloudwatch get-metric-statistics --namespace AWS/S3 \
  --metric-name BucketSizeBytes --dimensions Name=BucketName,Value=my-company-data-lake-raw Name=StorageType,Value=StandardStorage \
  --start-time 2026-09-01T00:00:00Z --end-time 2026-09-03T00:00:00Z --period 86400 --statistics Average

# Enable inventory reports for a large bucket (cheaper than listing millions of objects)
aws s3api put-bucket-inventory-configuration --bucket my-company-data-lake-raw --id weekly-inventory --inventory-configuration file://inventory-config.json
```

### IaC Best Practices

- Always pair `aws_s3_bucket` with an explicit `aws_s3_bucket_public_access_block` — don't rely on account defaults.
- Manage the bucket name via a variable + naming convention (`${var.project}-${var.env}-${var.zone}`) to avoid global name collisions.
- Turn on versioning for curated/gold zones; it's cheap insurance against bad pipeline runs.
- Use **S3 Bucket Keys** (`bucket_key_enabled = true`) with SSE-KMS to cut KMS request costs at scale.
- Keep Terraform state itself in a separate, tightly-locked-down S3 bucket — never reuse a data bucket for state.
- Add `abort_incomplete_multipart_upload` lifecycle rules — failed multipart uploads silently accumulate storage cost otherwise.

## Python (boto3)

```python
import boto3
from botocore.exceptions import ClientError

s3 = boto3.client("s3", region_name="us-east-1")

# Create a bucket
def create_bucket(bucket_name: str, region: str = "us-east-1"):
    if region == "us-east-1":
        s3.create_bucket(Bucket=bucket_name)
    else:
        s3.create_bucket(
            Bucket=bucket_name,
            CreateBucketConfiguration={"LocationConstraint": region},
        )

# Upload a file with server-side encryption
def upload_file(local_path: str, bucket: str, key: str):
    s3.upload_file(
        Filename=local_path,
        Bucket=bucket,
        Key=key,
        ExtraArgs={"ServerSideEncryption": "aws:kms"},
    )

# List objects under a partitioned prefix
def list_partition(bucket: str, prefix: str):
    paginator = s3.get_paginator("list_objects_v2")
    for page in paginator.paginate(Bucket=bucket, Prefix=prefix):
        for obj in page.get("Contents", []):
            print(obj["Key"], obj["Size"], obj["LastModified"])

# Generate a presigned URL (e.g. for a downstream consumer)
def presigned_url(bucket: str, key: str, expires_in: int = 3600) -> str:
    return s3.generate_presigned_url(
        "get_object",
        Params={"Bucket": bucket, "Key": key},
        ExpiresIn=expires_in,
    )

# Read a file directly into memory (e.g. small JSON config)
def read_object(bucket: str, key: str) -> bytes:
    response = s3.get_object(Bucket=bucket, Key=key)
    return response["Body"].read()

# Copy objects between zones (e.g. raw -> processed) without downloading
def copy_between_zones(bucket: str, src_key: str, dst_key: str):
    s3.copy_object(
        Bucket=bucket,
        CopySource={"Bucket": bucket, "Key": src_key},
        Key=dst_key,
    )

# Batch-delete objects (e.g. cleaning up a failed run's partial output)
def delete_prefix(bucket: str, prefix: str):
    paginator = s3.get_paginator("list_objects_v2")
    for page in paginator.paginate(Bucket=bucket, Prefix=prefix):
        objects = [{"Key": obj["Key"]} for obj in page.get("Contents", [])]
        if objects:
            s3.delete_objects(Bucket=bucket, Delete={"Objects": objects})

# Read a CSV/Parquet directly into pandas without downloading to disk
def read_parquet_to_dataframe(bucket: str, key: str):
    import pandas as pd
    import io
    obj = s3.get_object(Bucket=bucket, Key=key)
    return pd.read_parquet(io.BytesIO(obj["Body"].read()))

# Check whether an object exists (common "did the upstream job finish" check)
def object_exists(bucket: str, key: str) -> bool:
    try:
        s3.head_object(Bucket=bucket, Key=key)
        return True
    except ClientError as e:
        if e.response["Error"]["Code"] == "404":
            return False
        raise

# Multipart upload for very large files, with progress callback
def multipart_upload(local_path: str, bucket: str, key: str):
    from boto3.s3.transfer import TransferConfig
    config = TransferConfig(multipart_threshold=1024 * 25, max_concurrency=10)

    def progress(bytes_transferred):
        print(f"Transferred {bytes_transferred} bytes")

    s3.upload_file(local_path, bucket, key, Config=config, Callback=progress)

if __name__ == "__main__":
    try:
        list_partition("my-company-data-lake-raw", "events/year=2026/month=09/")
    except ClientError as e:
        print(f"S3 error: {e.response['Error']['Message']}")
```

### boto3 Tips

- Use `paginator`s for `list_objects_v2` — never assume a single call returns everything (max 1,000 keys per page).
- For large uploads, use `s3.upload_file()` (handles multipart automatically) rather than `put_object()` with raw bytes.
- Wrap calls in `try/except ClientError` and inspect `e.response["Error"]["Code"]` for retry logic (e.g. `SlowDown` on throttling).
- Use `boto3.resource("s3")` instead of the client when you want a more Pythonic, object-oriented interface (`bucket.objects.filter(Prefix=...)`).
- `head_object` is cheaper than `list_objects_v2` + filter when you just need to check if one specific key exists.
- For buckets with millions of objects, use **S3 Inventory** reports (a daily/weekly manifest file) instead of `list_objects_v2` loops — far cheaper and faster.

## Security Best Practices

- Block all public access at the bucket level by default; only open specific prefixes via bucket policy if truly required (e.g. a public data share).
- Enforce encryption in transit (`aws:SecureTransport`) and at rest (SSE-KMS) via bucket policy `Deny` statements, not just defaults — defaults can be overridden by a misconfigured client.
- Use **S3 Access Points** when many different applications/teams need scoped access to the same bucket — cleaner than one giant bucket policy.
- Enable **S3 Access Logs** or **CloudTrail data events** for buckets holding sensitive data, and route them to a separate, locked-down logging account.
- Prefer bucket policies with IAM role principals over IAM user access keys for any cross-account or cross-service access.

## Cost Optimization

- Use **Intelligent-Tiering** for datasets with unpredictable access patterns — it moves objects between tiers automatically with no retrieval fees.
- Set lifecycle rules to transition `raw/` data to IA/Glacier after the active processing window closes; most raw data is rarely re-read after curation.
- Batch small files into larger ones (target 128 MB–1 GB per file) before writing to S3 — millions of tiny files inflate both storage overhead and downstream query planning time in Athena/Spark.
- Use **S3 Storage Lens** to get organization-wide visibility into which buckets/prefixes are driving cost.
- Delete or archive `tmp/` and failed-job output automatically via lifecycle rules rather than manual cleanup.

## Monitoring & Common Errors

| Symptom                                        | Likely Cause                                                         | Fix                                                                               |
| ---------------------------------------------- | -------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| `403 AccessDenied`                             | Missing IAM permission, bucket policy `Deny`, or Block Public Access | Check policy simulator; verify SSE-KMS key policy grants the caller `kms:Decrypt` |
| `SlowDown` (503)                               | Exceeding request-rate limits on a single prefix                     | Add random hex prefixes to keys, or spread load across more prefixes              |
| Athena query scans way more data than expected | Files not partitioned or too many small files                        | Repartition; run `MSCK REPAIR TABLE` or a Glue crawler; compact small files       |
| Objects "disappear" after a job re-run         | Versioning off + overwrite from another job                          | Enable versioning; use unique run-scoped prefixes                                 |
| High KMS cost                                  | `bucket_key_enabled` not set, causing a KMS API call per object      | Enable **S3 Bucket Keys** to reduce KMS request volume                            |

Monitor via CloudWatch metrics `BucketSizeBytes`, `NumberOfObjects`, `4xxErrors`, `5xxErrors`, and set alarms on `4xxErrors` spikes to catch permission regressions early.
